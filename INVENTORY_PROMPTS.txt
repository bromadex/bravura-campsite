INVENTORY MANAGEMENT (IN) MODULE — IMPLEMENTATION PLAN
═══════════════════════════════════════════════════════════════════════════════

Module code: IN   |   T-codes: IN01–IN10   |   Color: #B45309 (amber-brown, TBD)
Permission gates: NEW inventory.view / create / edit / delete / approve
                  (seed in permissions table; supplies.* stays for campsite legacy)

One store of record for every physical thing Bravura holds: camp supplies,
fleet spare parts, meals dry goods, PPE, tools. Absorbs the campsite
supplies/stock-transfers feature and becomes the consumer of procurement
requisitions.

STARTING POINT (from codebase survey, 2026-07-13)
  • camp_supply_items / camp_supply_txns / camp_supply_balance / stock_transfers
    exist in the live DB but have NO tracked CREATE TABLE migration — created
    directly in Supabase. Must be reverse-engineered and formalized first.
  • CampSupplies.jsx + StockTransfers.jsx (campsite module) are fully built
    against those tables via CampsiteContext.
  • procurement_requisitions (0028) is a ready cross-module hook — fuel already
    auto-writes to it. procurement_suppliers (0058) + Suppliers.jsx built.
  • fleet_maintenance_parts are ad-hoc line items per repair — no stock on hand.
  • Meals has no ingredient/dry-goods tracking at all.
  • Migration numbering: next general number is 0087 (0100–0149 reserved HR).

CROSS-MODULE INTEGRATION POINTS
───────────────────────────────────────────────────────────────────────────────

  Procurement → requisitions raised from low stock; receipts close them
  Campsite    → camp supplies absorbed into IN (categories: supplies)
  Fleet       → maintenance parts issued from stock
  Meals       → kitchen dry goods issued from stock
  HR/CL       → PPE and tool issue per employee/contractor worker
  Fuel        → lubricants and filters as stock items
