MODULE OVERVIEW
═══════════════════════════════════════════════════════════════════════════════

The Project Module manages construction/mining projects across Bravura sites.
It tracks project lifecycle from planning through execution to closeout, with
full cost tracking that aggregates data from existing modules (contractors,
fleet, inventory, meals, HR/workforce).

Module code: PJ
Permission pattern: projects.view / projects.create / projects.edit /
                    projects.delete / projects.approve
T-code range: PJ01–PJ20

Key differentiator: This is a CROSS-MODULE AGGREGATION layer. Projects don't
duplicate data — they link to existing records (fleet trips, contractor hours,
inventory issues, equipment usage) via a project_id FK on those tables.

PHASE 3 — COST TRACKING & CROSS-MODULE LINKING
═══════════════════════════════════════════════════════════════════════════════
Migration: 0087_project_costs.sql

Schema changes (add project_id to existing tables):
  ALTER TABLE fleet_trips ADD COLUMN project_id UUID REFERENCES projects(id);
  ALTER TABLE equipment_usage_log ADD COLUMN project_id UUID REFERENCES projects(id);
  ALTER TABLE inventory_issues ADD COLUMN project_id UUID REFERENCES projects(id);
  ALTER TABLE hired_equipment ADD COLUMN project_id UUID REFERENCES projects(id);
  ALTER TABLE hired_vehicles ADD COLUMN project_id UUID REFERENCES projects(id);
  ALTER TABLE casual_timesheets ADD COLUMN project_id UUID REFERENCES projects(id);

New table:
  project_cost_entries (for manual/miscellaneous costs not from other modules)
    - id UUID PK
    - project_id UUID NOT NULL FK projects
    - phase_id UUID FK project_phases
    - cost_category TEXT NOT NULL ('labour','materials','equipment','transport','fuel','other')
    - description TEXT NOT NULL
    - amount NUMERIC(14,2) NOT NULL
    - cost_date DATE NOT NULL
    - vendor TEXT
    - reference_number TEXT
    - approved BOOLEAN DEFAULT false
    - approved_by UUID FK auth.users
    - notes TEXT
    - is_archived BOOLEAN DEFAULT false
    - created_at TIMESTAMPTZ DEFAULT now()

RPC: rpc_project_cost_summary(project_id UUID)
  Returns aggregated costs from all linked modules:
    - Fleet trips (fuel cost from fleet_trips where project_id = X)
    - Equipment hours (equipment_usage_log × hourly_rate)
    - Materials (inventory_issues value where project_id = X)
    - Hired equipment (hired_equipment daily_rate × days)
    - Hired vehicles (hired_vehicles daily_rate × days)
    - Casual labour (casual_timesheets hours × rate where project_id = X)
    - Manual entries (project_cost_entries)
  Grouped by cost_category with subtotals.

Pages:
  PJ06 — ProjectCosts.jsx
    - Budget vs Actual gauge (% spent)
    - Cost breakdown by category (stacked bar or pie)
    - Cost trend over time (line chart)
    - Detailed line items from all sources
    - Manual cost entry form
    - Filter by phase, category, date range
    - Link to source record (click → navigate to fleet trip, inventory issue, etc.)

IMPLEMENTATION NOTES
═══════════════════════════════════════════════════════════════════════════════

1. Module registration:
   - Add to permissions table: projects.view/create/edit/delete/approve
   - Add MODULE_COLORS.projects in utils/permissions.js
   - Add projectsNav to navigation config
   - Add PROJECT_PILLS to QuickNav.jsx
   - Add module tile to HomeLauncher.jsx
   - Register routes in App.jsx

2. Cross-module linking strategy:
   - Adding project_id to existing tables is OPTIONAL on those tables
   - When creating a fleet trip, equipment usage, inventory issue, etc.,
     the user gets a "Project" dropdown (only shows active projects)
   - The project cost RPC aggregates by querying WHERE project_id = X
   - This means NO data duplication — single source of truth

3. Project codes:
   - Auto-generated: PJ-001, PJ-002, etc. (per site)
   - Stored in module_settings table (like employee numbers BRA-xxx)

4. Dashboard connects to contractor module:
   - Equipment usage linked via project_id on equipment_usage_log
   - Hired vehicles linked via project_id on hired_vehicles
   - Casual timesheets linked via project_id on casual_timesheets
   - This gives instant project costing without manual entry

5. Migration numbering: 0085–0089 (general range, not HR)
